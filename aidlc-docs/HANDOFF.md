# VALORANTプレイヤー分析ダッシュボード 引き継ぎ書

更新日 2026年11月21日

> **現在の進捗**：この文書は画面設計着手前の記録。画面設計・初版実装の後、提供された開示ZIP 1件で対戦・ストア取引の形式差を修正し、4カテゴリをChromeで検証した。次は[モバイル実機レビュー](construction/review.md)。公開・登録は未実施。

Riot Gamesから開示されたZIPをスマートフォンで開き、VALORANTのプレー記録、通報、課金、ストア取引を日本語で見られる静的サイトを作る。ZIPの展開から表示までを端末内で行う。AI-DLCのInceptionで[要件定義の初稿](inception/requirements.md)をまとめ、ユーザーから「OK」と引き継ぎ書の作成依頼を受けた。次に着手するのはスマホ優先の画面設計。サイト本体、GitHubリポジトリ、GitHub Pagesへのデプロイは着手前。

## ここまでの流れ

1. 添付されたRiotの開示ZIPをローカルで調査した。全36ファイルから `valorant/` 配下の5つのJSONだけを展開できた。Riotアカウントや他タイトルのファイルは画面に不要で、読み飛ばせる。
2. 試作したJavaScriptで、その構成を再現した架空のテストZIPをオフラインのChromeで解析できた。同じ解析コードを添付ZIPに対して手元で実行し、5ファイルを読めることも確認した。iPhone・Androidの実機確認は実装後に行う。
3. 添付ZIPとXの公開画像から、通報集計の形式と理由コード10種類を確認した。別の画像付き投稿も16件調べた。「通信妨害」という翻訳表記はあったが、元コードは未確定。確認済みの10種類は[要件定義の対応表](inception/requirements.md#通報の表示名)に記載した。 [両方向の生JSONが写っている投稿](https://x.com/miudukisecond/status/2123716002911555861) · [別の生JSON](https://x.com/Zer0two_02valo/status/2123598161117880338) · [翻訳のみの候補](https://x.com/mizurato9/status/2124046247149686971)
4. 添付画像 `VALORANTプレイヤー分析ダッシュボード.png` をUIの参考に、スマホを主画面とする要件を定義した。初版の公開先はGitHub Pagesを想定。GitHub Freeでは公開リポジトリから標準の `github.io` URLにHTTPSで配信できる。 [GitHub Pages公式ガイド](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages)

## データの扱い

以下は添付ZIPで確認したファイル名。パスはすべて `valorant/` 配下。Riotの公式案内でVALORANT欄に明記されているのはストア取引と通貨購入の履歴なので、対戦履歴や通報集計は欠落時もほかの画面を使える設計にする。 [Riotのデータ請求案内](https://support.riotgames.com/ja-jp/riot/account/request-personal-account-data-and-history)

| ファイル | 確認した内容と扱い |
| --- | --- |
| `valorant_match_history_uc.json` | 試合の開始・終了時刻、モード、種別、勝敗。試合時間は開始・終了の差から計算する。初期表示の対戦指標はマッチメイキングを対象とし、コンペ勝率には勝敗が判明しているコンペ試合を使う。 |
| `valorant_grouped_reports.json` | `reports_made` と `reports_received` は、データがある場合に理由コードと件数の組として入る。両者に同じ対応表を使う。未登録コードは元の表記と件数を出し、`null` や未収録は「データなし」。日付がない集計なので、試合の期間フィルターは適用しない。 |
| `valorant_payment_event_uc.json` | 決済日時、通貨コード、支払額の `real_currency_paid_x100`、付与されたゲーム内通貨。支払額は通貨別に集計する。 |
| `valorant_purchase_event_uc.json` | アイテム名、取引日時、ゲーム内通貨の種類と消費量、取引区分。消費量が `null` の取引も明細に残す。集約時は通貨ごとに扱う。 |
| `valorant_audio_transcripts_uc.json` | 添付ZIPでは配列が空。内容の形式は未確認で、文字起こし画面は初版の対象外。 |

対戦履歴と決済の日時はフィールド名に `_utc` があり、サンプルの文字列にはタイムゾーン指定がなかった。ストア取引日時には明示的なタイムゾーンのある値とない値が混在した。日付の解釈と表示タイムゾーンは、月別集計を実装する前に決める。

検証に使った実ZIPと参考画像の原本は会話の添付にある。実ZIPには個人データが含まれるため、必要なときだけローカルで参照する。公開リポジトリ、デモ、テスト用のサンプルZIPには架空データを使う。

## 画面と初版の範囲

- スマホでは「ZIPを開く」と架空データの「デモを見る」から開始する。取込後は対戦数・合計試合時間・コンペ勝率を上部に置き、主要情報は縦1列で読めるようにする。下部ナビは「ホーム」「プレー記録」「その他」。PCではサイドバーと複数列のカードを使う。
- 明るい背景、青系のグラフ、概要カードから明細へ進む構成を参考画像から取り入れる。最近の試合には日時・モード・勝敗・所要時間を表示する。参考画像にあるRiot ID、エージェント肖像、マップ、ラウンドスコアは初版の表示範囲外。
- 結果の共有、履歴の永続保存、Riotとのアカウント連携は初版の対象外。読み込んだデータはブラウザのメモリに置き、別のZIPを開いたときは表示を入れ替える。

| 4 | **受け入れ確認** | iPhone Safari、Android Chrome、PCでファイル選択と閲覧を通す。360・390・768・1280pxでレイアウトを確認する。欠損・破損ZIP、未知の通報コード、複数通貨、読み直し・消去を試す。ページ取得後はオフラインでも動き、オンラインの読み込み中もZIPや集計値を送信しないことを確認する。 |
| 5 | **公開準備と公開確認** | サイト名・公開先リポジトリを決め、配信対象に実データが入っていないことを確認する。Riot Developer Portalでプレイヤー向け製品の登録に対応し、GitHub Pagesに公開したHTTPS URLで主要導線を確認する。 |

Riotの公開ポリシーでは、公式APIの利用有無を問わずプレイヤー向け製品にDeveloper Portal登録が求められる。サイトの名称・アイコンは独自のものを使い、非公式と分かる表示を設計する。 [VALORANT開発者ポリシー](https://developer.riotgames.com/docs/valorant) · [Riotのファンプロジェクト方針](https://www.riotgames.com/en/legal)
