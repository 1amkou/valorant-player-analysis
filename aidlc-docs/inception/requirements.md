# VALORANTプレイヤー分析ダッシュボード 要件定義

AI-DLCのInceptionでレビューする初版案。スマートフォンだけで、Riot GamesからダウンロードしたZIPを開き、VALORANTのプレー記録と通報、課金、ストア取引を日本語で確認できる公開サイトを作る。

## 対象ユーザーと利用の流れ

主な利用者は、PCを持たず、普段スマートフォンで情報を確認するプレイヤー。Riotから届いたZIPを端末の「ファイル」や「ダウンロード」に保存し、サイトの「ZIPを開く」から選ぶ。読み込み後はホームで全体を見て、気になる項目の詳細へ進む。PCでも同じ機能を利用できる。

## 機能要件

| ID | 項目 | 初版の要件 |
| --- | --- | --- |
| FR1 | ZIPの読み込み | iPhoneとAndroidのファイル選択から受け取ったZIPを丸ごと開く。事前の手動解凍は不要。PCではドラッグ＆ドロップにも対応する。ZIPの目次から対象の `valorant/` JSONを選び、必要なファイルだけを解析する。 |
| FR2 | ホーム | 最終プレー日時、対戦数、合計試合時間、コンペ勝率を上部に表示する。続けて、プレー推移、モード別内訳、通報、課金、ストア取引、最近の試合を表示する。取込前は「ZIPを開く」と架空データの「デモを見る」を表示する。デモには「サンプルデータ」と明記する。 |
| FR3 | プレー記録 | 月別の対戦数・試合時間とモード別の内訳を表示する。試合一覧には日時、モード、勝敗、所要時間を表示し、期間・モードで絞り込める。コンペ勝率は勝敗が判明しているコンペ試合の勝数 ÷ 対象試合数。対象試合がなければ「データなし」。合計試合時間は対象試合の終了時刻と開始時刻の差の合計。 |
| FR4 | 通報 | 「送った通報」「受けた通報」を独立して表示し、理由別の件数を確認できる。確認済みの10コードに日本語名を表示し、未登録コードは元の表記と件数を表示する。`null` や未収録は「データなし」とする。試合の期間フィルターに連動せず、ZIPに収録された集計を表示する。 |
| FR5 | 課金 | 決済履歴から、記録された支払額と決済回数、月別推移、決済明細を表示する。支払額は通貨ごとに集計し、明細に日時・金額・付与されたゲーム内通貨を表示する。 |
| FR6 | ストア取引 | ゲーム内通貨の種類別消費量と取引件数を表示する。明細にアイテム名、取引日時、消費量、購入・ギフト・アンロック等の区分を表示する。消費量が未記録の取引は明細に残し、消費量の集計対象は数値のある取引とする。 |
| FR7 | 空・エラー・入れ替え | ZIP選択キャンセル、破損・対応外のZIP、VALORANTデータなし、カテゴリの欠落、解析中を区別する。一部のJSONが欠けている、または読めない場合は、読めた項目を表示して該当セクションに状態を示す。別のZIPの読み込みと表示データの消去ができる。 |

### 通報の表示名

| ZIPのコード | 表示名 |
| --- | --- |
| `ABUSING_GLITCHES` | グリッチの悪用 |
| `AFK` | 離席・放置 |
| `BOTTING` | ボット使用 |
| `CHEATING` | チート行為 |
| `COMMS_ABUSE_TEXT` | テキストチャットでの迷惑行為 |
| `COMMS_ABUSE_VOICE` | ボイスチャットでの迷惑行為 |
| `INAPPROPRIATE_TEAM_NAME` | 不適切なチーム名 |
| `OFFENSIVE_NAME` | 不適切なプレイヤー名 |
| `RANK_MANIPULATION` | ランク操作 |
| `SABOTAGING_TEAM` | 味方への妨害 |

「送った通報」「受けた通報」の両方が理由コードと件数で入る実例を確認済み。 [通報集計の公開例](https://x.com/miudukisecond/status/2123716002911555861) · [カテゴリの公開例](https://x.com/Zer0two_02valo/status/2123598161117880338)

## レスポンシブUIと品質要件

| ID | 項目 | 初版の要件 |
| --- | --- | --- |
| NFR1 | スマホ優先 | 参考画像の明るい背景、青系のアクセント、数値カード、グラフを使う。スマホは1列で、ZIPを開く導線と主要な数字を先に表示する。下部ナビは「ホーム」「プレー記録」「その他」。PCではサイドバーと複数列のカードを使う。 |
| NFR2 | タッチ操作と読みやすさ | 横スクロールなしで主要情報を読め、明細は画面幅に応じて行表示へ切り替える。グラフの値はタップやキーボード操作で確認でき、見出しや数値でも把握できる。勝敗や読込状態は色と文字で伝える。 |
| NFR3 | 端末内処理 | ZIPの展開、JSON解析、集計、描画をブラウザ内で行う。サイト配信用の資材は同梱し、解析・広告の外部サービスやゲームAPIへの接続を設けない。ユーザーのデータはページのメモリに保持し、ブラウザの永続ストレージには保存しない。 |
| NFR4 | 安定した読み込み | 処理中も画面の操作を妨げない。ZIPのサイズや展開量を制限し、制限や対応形式に達したときは理由を日本語で伝える。上限値はモバイルの実測に基づいて決める。 |
| NFR5 | 公開構成 | GitHub Freeの公開リポジトリとGitHub Pagesの標準HTTPS URLを初版の公開先とする。リポジトリに置くのはサイトのソースと架空のテストデータ。Riotへのデータ請求・ダウンロードはRiotのサイトで行う。 [GitHub Pages公式ドキュメント](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages) |

## 初版案で置いた前提

- 初期表示の対戦指標はマッチメイキングの記録を対象とする。射撃場・チュートリアル・カスタムは、対象外のプレー記録として切り替えて確認できる。
- ホームの最近の試合には、ZIPで裏付けられる日時・モード・勝敗・所要時間を載せる。参照画像にあるRiot IDやエージェント肖像、マップ・ラウンドスコアは初版の表示範囲外。課金や通報のサンプル値には架空の数値を使う。
- ボイスチャットの文字起こしは、内容が入ったサンプルで形式を確認できた段階で扱う。結果共有、履歴の保存、Riotとのアカウント連携も初版の対象外。
- 公開サイトの名称とアイコンは独自のものを使い、Riot公式サービスと区別できる表示にする。Riotはプレイヤー向け製品にDeveloper Portal登録を求めているため、公開工程で対応する。 [VALORANT開発者ポリシー](https://developer.riotgames.com/docs/valorant) · [Riotのファンプロジェクト方針](https://www.riotgames.com/en/legal)

## 初版の受け入れ条件

1. iPhoneのSafariとAndroidのChromeで、端末のダウンロードからZIPを選び、ホームと各詳細を閲覧できる。デスクトップでも同じ集計結果を確認できる。
2. 画面幅360px・390px・768px・1280pxで、ファイル選択ボタン・主要指標・ナビゲーションが操作でき、主要画面に横スクロールが発生しない。
3. ページの読み込み完了後、オフラインでもZIP選択から表示まで成功する。オンラインでも読み込みから詳細表示までに、ZIPや集計結果の送信・外部リソースへの要求が発生しない。
4. 同じZIPを再読込しても集計が重複しない。別のZIPを開くと表示が入れ替わり、消去やページ再読込で元のデータが画面から消える。
5. 既知と未登録の通報理由、受けた通報の `null`、欠けたJSON、複数の決済通貨、数値が未記録のストア取引を、各要件どおりに処理する。公開用のデモ・テストでは架空データを使う。

## 次の設計工程

要件レビュー後に、スマホの「読込前 → 読込中 → ホーム → 詳細」と、PCのカード配置をワイヤーフレームにする。実装方式、モバイルでのファイル上限、公開URLと配信手順は設計工程で詰める。 [AWS AI-DLCのInception](https://awslabs.github.io/aidlc-workflows/reference/04-stages/inception/)
