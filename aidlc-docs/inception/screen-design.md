# 画面設計｜VALORANTプレイヤー分析ダッシュボード

[要件定義](requirements.md) · [引き継ぎ書](../HANDOFF.md) · [操作できるワイヤーフレーム](wireframe.html)

## 作りたいもの

Riotから受け取ったZIPを手動で解凍せず、スマホだけで、自分のVALORANTのプレー記録・通報・課金・ストア取引を日本語で見られる非公式の静的サイト。ZIPの展開・解析・集計は端末内で行い、データは送信・永続保存しない。PCでも同じ内容を閲覧できる。

画面例の明るい背景、青いグラフ、概要カードから詳細に進む構成を採用する。Riot ID・エージェント肖像・マップ・ラウンドスコア・ボイスチャット文字起こしは初版に並べない。共有、履歴保存、アカウント連携も初版の対象外。ワイヤーフレーム上の名称・アイコンは仮。

## 1. スマホの導線

```text
初回画面 ── ZIPを開く → 端末のファイル選択 → 読み込み中 → ホーム
          ├ 選択を閉じる → 元の画面（通知なし）             ├ すべて利用不可 → エラー・再試行
          └ デモを見る → ホーム（サンプルデータ表示）      └ 一部利用可 → ホーム（対象カードに状態）

ホーム ── 各カードの「詳細を見る」→ プレー記録／通報／課金／ストア取引
下部ナビ ── ホーム｜プレー記録｜その他 → 通報・課金・ストア取引・データ管理
データ管理 ── 別のZIPを開く → 成功時だけ入れ替え／失敗時は元の表示を維持
            └ 表示データを消去 → 確認 → 初回画面
```

- **初回**：「ZIPを開く」を主ボタン、「デモを見る」を副ボタンにする。「解凍不要」「ファイルは送信されません」を選択前に示す。PCは同じ場所にドロップ案内を追加。データ未読込のときは空のダッシュボードやナビを出さない。
- **読み込み中**：不確かなパーセントを出さず、「ZIPを確認中」「必要なデータを読み込み中」などステータスを通知する。取り消せる。既存データがあれば取り消し・失敗時は保持し、成功時のみ置き換える。ZIP選択のキャンセルはエラー扱いしない。
- **ホーム**：最終プレー日時と「対戦数・合計試合時間・コンペ勝率」を上部に置く。指標は初期状態でマッチメイキング。メインカードは縦1列で、プレー推移 → モード別内訳 → 通報 → 課金 → ストア取引 → 最近の試合。デモでは詳細画面にも「サンプルデータ」を表示する。
- **詳細**：スマホの明細は表の横スクロールではなく縦に並ぶ行表示。固定ナビは本文・操作部に重ならないよう下余白とセーフエリアを確保する。ナビ移動やカード遷移で見出しにフォーカスを移す。実装時はブラウザの戻る操作で直前の画面に戻せるようにし、個人データやファイル名はURLに含めない。

## 2. 詳細画面

| 画面 | 表示内容と操作 |
| --- | --- |
| プレー記録 | 期間・モードと、マッチメイキング／その他の切替。同じ条件を対戦数・試合時間・勝率・月別推移・モード内訳・一覧に適用し、ホームの概要や通報には波及させない。明細は日時・モード・勝敗・所要時間。コンペ勝率の分母は勝敗判明分のみ。 |
| 通報 | 「送った通報」「受けた通報」を独立させ、理由ごとに件数を表示。既知コードは日本語、未知コードは原文。`null`・未収録は「データなし」、明示的な0件は「0件」。日付フィルターなし。 |
| 課金 | 支払額は通貨ごとに表示し、異なる通貨を足さない。決済回数、通貨を切り替えられる月別推移、日時・金額・付与通貨の明細。 |
| ストア取引 | VP等の種類別消費量と取引件数。明細はアイテム名・日時・消費量・取引区分。量が `null` でも取引は残し「未記録」と出す。 |
| その他／データ管理 | スマホでは各詳細へのメニューも兼ねる。読み込み直し・消去を提供。消去の確認では元のZIPを削除しないと伝える。 |

## 3. エラーと空の表示

| 状態 | 表示・次の操作 |
| --- | --- |
| 破損／非対応 | 理由を分けて表示。「別のZIPを選ぶ」で再試行。対応外の圧縮形式を破損と決めつけない。 |
| 上限超過 | ZIPのサイズ／展開量のどちらか該当する上限を示す。具体値はモバイル実測後に決定。 |
| 対象データなし | 「VALORANTの対象データが見つかりません」。Riotから受け取ったZIPを案内し、再選択できる。対象JSONがすべて読めない場合は「対象データを読み込めません」と区別。 |
| 一部のJSONが欠落／読めない | 読めたカテゴリは通常表示し、該当カード・詳細だけに「未収録」／「読み込めませんでした」。両者を0件と表示しない。 |
| 正常な空データ／絞り込み結果0件 | 集計値は測れる場合のみ0。勝率など分母が0なら「データなし」。絞り込み結果が0件ならフィルターのリセットを案内する。 |

## 4. PCとアクセシビリティ

- 1024px未満では縦1列＋下部ナビ。1024px以上では左サイドバーに各ページへの入口を置き、ホーム上段に指標、続く段に「推移＋内訳」「通報＋課金」「ストア取引＋最近の試合」を並べる。
- 主要なタップ領域は44px以上を目安にする。色だけに頼らず勝敗・欠落を文字で明示する。グラフには数値表示を併設し、タップでもキーボードでも確認できるようにする。360・390・768・1280pxで横はみ出しと固定ナビを確認する。

## 5. レビュー方法と次工程

ワイヤーフレームはHTMLを直接開ける。「デモを見る」でホームと詳細、「ZIPを開く」で画面確認用メニューから成功・欠落・失敗・取り消しを試せる。**本物のファイル選択・ZIP解析・デプロイは未実装**。グラフや明細は架空データで、読み込み済みのサンプルを使った操作確認用。開き直すと初期画面に戻る。

WindowsのヘッドレスChromeで、360・390・768・1280pxの主要画面に横はみ出しがないことと、デモ、詳細への遷移、絞り込み、消去を確認した。390pxでは模擬読み込みの成功・取り消し・各エラー・一部欠落と、入れ替えに失敗しても前のデータが残ることも確認した。iPhone・Androidの実機テストではない。

レビューしたいのは、① 初回のZIP／デモの導線、② ホームで見る情報の順番、③ 「その他」と入れ替え・消去の場所。方向性が決まったら技術設計に進み、ZIPライブラリと別スレッド処理の要否、メモリ・展開量上限、日時の解釈と月境界、GitHub Pagesの相対パス配信を詰める。日時は `_utc` のタイムゾーン省略値をUTC候補とし、タイムゾーンなしのストア取引は実データの定義を確かめてから決める。公開前に実機・オフライン・データ非送信を確認し、Riot Developer Portalの製品登録に対応する。
